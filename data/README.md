# Canonical particle and decay tables

Every file here is in FastReso's canonical format, written by
`tools/convert_decay_data.jl` and split by `tools/split_by_provenance.py`. The
runtime reads them with `readparticles` / `readdecays`; the legacy AZYHYDRO and
THERMINATOR parsers live in `tools/converters/` and run once, not per load.

Two files per table: a **catalog** (`particles_*.dat`) and a **network**
(`decays_*.dat`). Splitting them is what lets one reader serve every source —
the old formats differed mostly in how they interleaved the two.

```text
particles: id name mass width degeneracy B S C Bot I Q [aliases...]
decays:    parent n_daughters branching_fraction daughters...
```

A decay row carries its parent ID, so a channel may live in a different file
from its particle header. That is how a supplement refers to daughters defined
by another layer.

## Layers

These are disjoint and additive: no species or channel appears twice, and
stacking them reproduces the whole-file references below exactly.

| layer | species | channel rows | notes |
|---|---:|---:|---|
| `light_pdg` | 351 | 1802 | hadrons PDG assigns an MC ID; **closed, loadable alone** |
| `light_qm` | 1167 | 18736 | quark-model states, no PDG MC ID exists |
| `sigma` | 1 | 2 | f0(500) only |
| `charm` | 91 | 370 | charm sector: open charm and charmonium |
| `bottom` | 59 | 90 | bottom sector: open bottom and bottomonium |

Load a stack by merging the parts:

```julia
names = ["light_pdg", "light_qm", "charm"]
dl = DecayList(
    reduce(merge, [readparticles("data/particles_$n.dat") for n in names]),
    reduce(merge, [readdecays("data/decays_$n.dat")   for n in names]),
)
```

Verified stacks — species, decay channels (self-channels excluded), all with
zero charge, baryon, unresolved-daughter or branching-range violations:

| stack | species | channels | equals |
|---|---:|---:|---|
| `light_pdg` | 351 | 1778 | — |
| `+ light_qm` | 1518 | 20514 | `QM2016Plus_isofix` |
| `+ sigma` | 1519 | 20516 | `QM2016Plus_isofix_sigma` |

## Whole-file references

Kept so a stack can be diffed against the table it came from.

| file | species | channel rows |
|---|---:|---:|
| `QM2016Plus` | 1518 | 20533 |
| `QM2016Plus_isofix` | 1518 | 20538 |
| `QM2016Plus_isofix_sigma` | 1519 | 20540 |
| `charm_bottom` | 150 | 460 |

`QM2016Plus_isofix` is the definition the layers are cut from. `isofix` is a
corrected variant rather than an increment — it *modifies* channels rather than
adding them — so it cannot itself be a layer.

## Provenance

**`QM2016Plus`** is upstream FastReso's own list
(`resonance_lists/decays_QM2016Plus_massorder.dat` at commit `a694de36`),
differing in exactly two lines, both corrections to declared daughter counts:

```text
9040221   n=2 -> 4   (the row lists four daughters)
20223     n=1 -> 2   (the row lists two)
```

Those are not cosmetic. This reader rejects nonzero padding beyond the declared
count, so upstream's file does not load here at all.

Of its 1518 species, **351 carry a PDG Monte-Carlo ID and 1167 do not** — the
latter are quark-model predictions with ad-hoc IDs, which is what the `QM` in
the name means. `pdg_audit.md` records that only `eta` and `omega` can be
regenerated from PDG on their own; the rest is curated, with branching ratios
assigned by hand (f0(980) at `0.620320856`, a1(1260) at `0.7 / 0.3`, rho(1450)
at `0.825 / 0.125 / 0.05`).

**`sigma`** is f0(500) at `m = 0.475 GeV, Gamma = 0.55 GeV`. The pole is
genuinely disputed, which is why it is a separate layer rather than part of the
light table. `spectral_function_plan.md` measures what it costs: a constant-width
Breit-Wigner puts **2.56% of its weight below the pi-pi threshold**, worth
+7.4% on pion dN/dy and +17% at pT = 1 GeV.

**`charm` / `bottom`** are split from `charm_bottom`, generated by
`tools/gen_heavy_flavour.py` against a pinned PDG release whose edition, schema
and citation are recorded in the file header. All 150 species are PDG-numbered,
so there is no quark-model layer for heavy flavour — the five `9xxxxxx` IDs are
PDG's own range for exotic and unconfirmed states, not invented.

Retained branching ratios are **absolute**: omitted probability is not
redistributed. Quarkonia therefore sum to well under one — `Upsilon(1S)` to
`0.0002`, `J/psi` to `0.127` — because most of their width goes to modes this
table cannot represent. `validate` reports these as branching-ratio outliers;
they are the documented policy, not an error. It does mean a J/psi emits 12.7%
of the daughters its width implies.

## Two rules the split had to respect

**A parent's channel block moves as a unit.** `merge` treats it as
all-or-nothing and rejects a parent defined in two files with different
channels. So a PDG-numbered parent with any quark-model daughter hands its
*whole* block to `light_qm`, keeping only its header in `light_pdg`, where it
reads as terminal. That moves 145 channels across 24 parents, and is why
`light_pdg` has 1778 channels rather than 1899.

**Membership is decided by asking PDG, not by inspecting the digits.** The
`9xxxxxx` range is PDG's own for exotic states — `9000221` is f0(500) — so an
ID-magnitude test calls those invented, while short ad-hoc IDs like `910`
(`Delta(2420)-`) slip past it the other way.

Separately, net flavour numbers cannot select a *sector*: quarkonia carry
`C = 0` and `Bot = 0` because quark and antiquark cancel, so partitioning
`charm_bottom` by net flavour files every J/psi, Upsilon, chi_c and chi_b under
neither heading — 32 of 150 species. Use `hasflavour(particle, 4)` for the
sector and `ischarm(particle)` for open flavour.

## Regenerating

```bash
julia --project=. tools/convert_decay_data.jl azyhydro SOURCE.dat \
    --particles-out data/particles_X.dat --decays-out data/decays_X.dat

python tools/split_by_provenance.py \
    data/particles_QM2016Plus_isofix.dat data/decays_QM2016Plus_isofix.dat \
    --stem light                                   # -> light_pdg, light_qm

python tools/split_by_provenance.py \
    data/particles_charm_bottom.dat data/decays_charm_bottom.dat \
    --stem heavy --split flavour                   # -> charm, bottom
```

The splitter needs the `pdg` package, as `tools/audit_pdg.py` and
`tools/gen_heavy_flavour.py` do.
